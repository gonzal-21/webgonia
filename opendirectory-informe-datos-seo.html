Base de datos, recolección y analítica de datos para SEO

Informe de diagnóstico y recomendaciones. Nivel profesional. Basado en el estado actual del repositorio.

1. Diagnóstico del estado actual

  • No hay base de datos. Las empresas están en arreglos JS embebidos en cada página (opendirectory.html, 100 registros demo en la página de Punta Arenas). El panel admin y el registro guardan en localStorage (od-admin-state, od-business-requests), es decir, solo en el navegador de cada usuario: no se comparte ni se puede analizar.
  • Datos duplicados. Varias páginas repiten los mismos datos; cualquier corrección exige editar muchos archivos.
  • SEO mínimo. Las páginas tienen title y meta description (la principal), pero no hay sitemap.xml, robots.txt, URL canónicas, Open Graph ni datos estructurados. Las fichas de empresa se generan con JS, sin URL propia: un buscador no puede indexarlas individualmente.
  • Sin analítica. No se mide búsquedas, clics ni altas, así que no hay base para decidir (ver el informe de estrategia).
  • Calidad. Hay registros verified:false junto a un texto que promete «información verificada».

4. Mejoras SEO técnico y de contenido

  1. Una URL por entidad: /empresa/patagonia-trek, /categoria/turismo, /comuna/puerto-natales, /turismo/puerto-natales. Generarlas como HTML estático desde los datos (generador de sitio) para que sean indexables sin JS.
  2. sitemap.xml y robots.txt generados desde la base, con lastmod.
  3. Etiquetas por página: title y description únicos, link rel="canonical", Open Graph, hreflang es/en.
  4. Datos estructurados JSON-LD (LocalBusiness, BreadcrumbList); ejemplo: 
    {"@context":"https://schema.org","@type":"LocalBusiness",
 "name":"Patagonia Trek","address":{"@type":"PostalAddress",
 "addressLocality":"Puerto Natales","addressCountry":"CL"},
 "geo":{"@type":"GeoCoordinates","latitude":-51.73,"longitude":-72.5}}
  5. Rendimiento (Core Web Vitals): imágenes optimizadas, CSS/JS inline pequeño (hoy es una ventaja), sin bloqueo de render.
  6. Contenido local: guías por territorio y temporada, noticias (data/news.json), enlaces internos entre categoría, comuna y empresa.
  7. Redirecciones: mantener los archivos con nombres antiguos como redirecciones; considerar 301 reales si se cambia de alojamiento.

Preferir herramientas respetuosas de la privacidad (Plausible, Umami, o analítica propia) y evitar identificadores personales; si se usa Google Analytics, añadir aviso de cookies.

Ejemplo de consulta: búsquedas sin resultados, que indican categorías o empresas faltantes:

SELECT query, COUNT(*) AS n FROM event
WHERE type='search' AND results=0
GROUP BY query ORDER BY n DESC LIMIT 20;

7. Riesgos y preguntas abiertas

  • ¿Quién es responsable de verificar y actualizar los datos? Sin un responsable, la base se degrada.
  • Con solo ~100 registros de demostración, el SEO depende de contenido propio útil, no de volumen. Las páginas casi vacías pueden perjudicar el posicionamiento.
  • ¿Qué métrica define el éxito: altas de empresas o visitas de turistas? Cambia qué se optimiza.
  • Las cifras y plazos de este informe son recomendaciones de criterio, no mediciones del sitio.
